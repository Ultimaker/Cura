## Summary

Custom improvements to the `USBPrinting` plugin, developed and tested against a
Geeetech M1 (Marlin, 250000 baud over COM6):

1. **Manual COM port / baud rate settings** — new `Extensions > USB Printing > USB Printing
   Settings...` dialog to pin port and baud rate, skipping the slow baud-rate
   auto-detection; the port scan loop only watches the configured port.
2. **Serial robustness hardening** — strict one-line-per-`ok` pacing, no position advance on
   readline timeouts while printing, write-timeout retry without skipping lines,
   resend-storm guard (pauses instead of re-executing old lines), stalled-print detection,
   and an optional timestamped TX/RX communication log (`usb-serial.log`).
3. **Reconnect / double-handle fix** — `reconnectWithManualSettings` and `addOutputDevice`
   close the stale device before creating a new one on the same port (fixes `WriteFile
   Access-denied` after printer reboots); the comm log now rotates to
   `usb-serial.prev.log` instead of being truncated, so the glitch trace survives
   reconnects and restarts.
4. **Maintenance routines** — new menu items *Prepare + Level* (`G28`/`G29` with no-ooze
   preheat, then full soak), *Purge Nozzle* and *Unload Filament*. Temperatures are
   resolved from the active material profile (never hardcoded); routines run only when
   connected and idle, a 0 °C hotend blocks, a 0 °C bed (valid e.g. for TPU) asks for
   confirmation, and `M190` is skipped for unheated beds.

## Testing

- New unit tests: `TestUSBPrintingManualSettings.py`, `TestUSBPrintingRobustness.py`,
  `TestUSBMaintenance.py` — run with `pytest plugins/USBPrinting/tests/ -v`.
- End-to-end verified on Cura 5.12 over real USB hardware: settings dialog, manual
  250000-baud connection, successful test print, maintenance menu items.
- Bed-heating scare during testing was root-caused via `usb-serial.log` to a stale TPU /
  empty material profile emitting `M140 S0` — i.e. sliced G-code content, not this plugin.

## Notes for reviewers

- This is a personal/custom fork targeting 8-bit Marlin boards with small RX buffers;
  defaults (burst of 1 line, ~120 s stall window) are conservative on purpose.
- i18n strings use the `cura` catalog like the rest of the plugin.
- Happy to split this into smaller PRs (settings / hardening / maintenance) on request.
